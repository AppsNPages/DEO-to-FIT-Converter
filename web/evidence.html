What is inside a DEO file?

This reader is based on the supplied ErgoRacer 2014 demo: 34 DEO files (26 distinct byte sequences), its bundled help, and static disassembly of ergoracer_2014_DEMO.exe. The Windows application was not executed. This is an independent implementation, not an official format specification.

From diary to analysis

The original diary selects rides and opens raw data, graphs, comparisons and summaries. The .T_L files are Windows-1252 text indexes containing filename stems, identifiers and comments. The .T_D files are binary diary companions; their full schema is not decoded. A standalone DEO contains the measurement records needed by this viewer.

Bundled help HILFE_EN01.rtf describes diary selection. HILFE_EN11.rtf documents time/distance axes, smoothing, selected regions, average and maximum values, and two power averages: including and excluding zero values. HILFE_DE04.rtf describes DEO and CSV interchange.

The native loader establishes the structure

At virtual addresses 0x404bd0–0x404c04, the executable reads a four-byte count n, then n × 40 bytes. Its CSV exporter starts at record one, skips metadata record zero, and advances by 40 bytes. Consequently there are n − 1 measurement records, beginning at file offset 44.

0           4           44                    4 + n × 40
┌───────────┬───────────┬─────────────────────┬────────────┐
│ count n   │ metadata  │ n−1 sample records  │ trailer    │
│ int32 LE  │ 40 bytes  │ 40 bytes each       │ 430 / 450  │
└───────────┴───────────┴─────────────────────┴────────────┘

The exporter names the fields

The native CSV labels at file offset 0x1bd6c8 specify seconds, km, watts, RPM, km/h, BPM, metres, °C, interval number and pause seconds. The argument loads at 0x4052ac–0x405303 connect these labels to exact byte offsets.

A concrete cross-check

20080828_173052_FLITZI.DEO is 316,154 bytes. Its count is 7,893, giving 7,892 samples. Sample 101 contains 205 W, 69 RPM and 142 BPM. The final distance is 56.7261428833 km. Sample 666 contains a nine-second pause. The arithmetic mean power, including zero values, is 123.461353269 W.

What the website calculates

Average and maximum values use the selected samples. Pedaling-only power excludes zero-watt samples. Distance is the final minus the first selected distance. Recorded duration is the timestamp span plus one recording interval. Work integrates each power sample until the next timestamp, using the first recording interval for the final sample. Pause seconds are displayed separately and are not added to recorded duration or work. Smoothing affects only the chart; summaries and CSV retain original values. Every chart channel has its own scale, normalized to 0–100% of that channel’s plotted range.

Compatibility is deliberately bounded

All supplied files have metadata flags 32, 430-byte trailers ; 33 have trailer marker 5555.0 and one has 0.0. The native writer also emits a final 20-byte block, so the reader accepts 450-byte trailers; this variant has a synthetic test, not a supplied real-world fixture. Additional recordings with header value 0 also pass the same record and FIT export checks; both 0 and 32 are accepted. The meaning of this header field remains unverified. Other header values, other trailer forms, non-increasing timestamps and malformed files are rejected explicitly. Core fields are established, but the full header and trailer semantics and exact advanced-analysis formulas remain unverified.

There is no claim of numerical equivalence for normalized power, intensity factor, training stress, elevation gain or best-effort profiles. These are not implemented. The original help also distinguishes sorted cumulative-duration curves from contiguous power profiles; neither is silently substituted for the other.

FIT activity export

The export uses the official Garmin FIT JavaScript SDK 21.218.0, bundled locally. It writes file identity, device information, timer events, records, one lap, one cycling session and an activity summary. No GPS coordinates or inferred training-stress metrics are created.

Confirm the original ride start in the export dialog. The computer’s current time zone is used automatically, with the offset applicable to that ride date. Nonexistent spring-transition times are rejected; ambiguous autumn-transition times use the earlier occurrence, following JavaScript Date. That date anchors the first DEO sample. For a selected section, prior recorded time and (when enabled) prior pauses shift its absolute start. Distance starts at zero. Pause values shift subsequent samples, matching the alternate native exporter at 0x405131–0x40515f; each internal pause becomes a timer stop/start pair. A pause after the last selected sample is outside the export. Active time includes one final recording interval; elapsed time additionally includes internal pauses.

FIT power, heart rate, cadence and temperature are rounded to whole units; distance is in metres (0.01 m resolution), speed in m/s (0.001 m/s), altitude in metres (0.2 m). Summary power/heart rate/cadence are weighted by recording duration. Work integrates the rounded exported power. Unknown DEO metadata, interval labels and reserved bytes are not exported to FIT. Unsupported numeric ranges cause an explicit error.
